# 注文の一生と、場合分けの一覧

この文書はコードから起こしたもので、推測は含まない。
出典は `internal/order/order.go`（状態遷移の正）と `app.js`（画面の配線）。

---

## 0. 軸は 3 本ある

| 軸 | 値 | どこで変わるか |
|---|---|---|
| `status` | pending → ready → completed（+ cancelled） | 厨房・受渡・記録表 |
| `paid` | false ↔ true | **受渡・支払い口・記録表のどこからでも** |
| `session` | 営業回（既定 `default`） | 記録・売上の「締めて次の回を始める」 |

`paid` は `status` に混ざっていない（`order.go` の Order 構造体のコメント参照）。
「渡したのに未払い」＝取りはぐれを集計に出すための設計で、
**status の一本道を追っても支払いは追えない**。ここが読み取りにくさの中心。

---

## 1. 入口は 2 つ（`useTags` で割れる）

`useTags` は `config/useTags` に置かれ、**全端末で共有**される（`app.js`）。
受付の「番号札を使っています / 使っていません」ボタンで切り替わる。既定は ON。

**どちらの入口でも `paid` は false で始まる。** 受付が勝手に支払い済みにすることはない。

### 入口A: 番号札モード OFF —— 札を配らない

```
受付で商品を選ぶ → 「注文を確定する」
  → placeOrder(immediate=true)
  → BuildOrder: status = ready, paid = false, tag = 0, number = ""
```

- **厨房を飛ばす**（作り置きをその場で渡すので焼き待ちには出さない）。
- **受渡には出る。** 受渡口で品物を渡し、代金もそこで受け取る。
- 支払い口の未払い欄にも出る（受渡口ではなく支払い口で受け取る運用にもできる）。
- 札が無いので、画面には受付順の通し番号を `受付12` のように出す（`numOf`）。
- 呼び出し表示には出ない（呼ぶための札が無いため）。

### 入口B: 番号札モード ON —— 札を渡す

```
受付で商品を選ぶ → 確認 → テンキーで実物の札番号を入力 → 最終確認
  → placeOrder(immediate=false, pickedTag=N)
  → BuildOrder: status = pending, paid = false, tag = N
```

- 札番号は**受付係が実際に取った実物の札**を打つ。山の並び順には依存しない。
- 確定の直前にサーバーの現在値を読み直して、在庫切れ・札の二重使用を弾く。
- 札モード ON で札なし確定が来たら弾く（`app.js`）。
  CSS の `display:none` だけで塞いでいると CSS 1 行で事故が戻るため、二重に止めている。

## 2. 本流

```
[pending]  厨房タブに伝票が並ぶ（受付順・経過3分/6分で色が変わる）
   │          ※ 入口A の注文はここを通らない
   │  厨房「用意した」
   │    ├ status = ready
   │    └ calledAt = now を同時に書く（呼び出しが自動で始まる）
   ↓
[ready]    受渡タブに出る／札があれば呼び出し表示で40秒間強調される
   │
   ├─ 受渡タブ  → §3
   └─ 支払い口タブ → §4
   ↓
[completed]
```

「用意した」は確認を挟まない（行列が詰まるため）。
代わりにトーストの「戻す」で 7 秒間だけ ready→pending に戻せる。

受渡の画面を開いている端末は、新しい受渡待ちが増えると一度だけ鳴る（`arrived`）。
入口A の注文は厨房を通らないので、これが無いと受渡口に何の合図も出ない。

---

## 3. 受渡タブ

厨房と同じ業務用の画面。1 枚のカードに「番号・品物・受け取る金額・押すところ」だけを出す。

| 注文の状態 | 出るボタン | 押すと |
|---|---|---|
| 支払い済み | **渡した** | `ready → completed` |
| 未払い | **N円 受け取って渡した** | `paid = true` → `ready → completed` |
| 未払い | 未払いのまま渡す（弱い） | 未払い確認ダイアログ（§3.1） |
| 札がある | 呼ぶ（弱い） | `calledAt` を今にして呼び出し表示で強調 |

未払いの注文は「受け取って渡す」が普通の道なので、**1 タップで済ませる**。
以前はどちらの道も確認ダイアログを通していたが、行列のなかで毎回 2 タップになり、
急ぐと「そのまま渡す」を押してしまっていた。
押し間違いは記録表から支払いも受渡も戻せる。

### 3.1 未払い確認ダイアログ（「未払いのまま渡す」から）

| ボタン | 結果 |
|---|---|
| 受け取って渡す | `paid = true` → `completed` |
| そのまま渡す | `completed` のまま **未払い** ＝ 取りはぐれとして集計に残る |
| 戻る | 何もしない |

完全に止めない理由: 現金を受け取ったのに打ち忘れていた場合に行列が止まるため。

---

## 4. 支払い口タブ

上のバーに **未収の件数と金額**、取りはぐれがあれば **「渡したのに未払い N件」** を赤で出す。
この数字は集計モジュール (WASM) を通さず画面側で数える。
現金を扱う画面なので、WASM が落ちている間も数字が消えてはいけない。

並ぶのは未払いの注文だけ。**「渡したのに未払い」を先頭に寄せる**（時間が経つほど回収できなくなる）。

| ボタン | 対象 | 結果 |
|---|---|---|
| N円 受け取る | 全ての未払い | 会計を開く → 確定で `paid = true` のみ |
| 受け取って渡した | **`status === 'ready'` のときだけ出る** | 会計を開く → 確定で `paid = true` + `ready → completed` |

会計を開くと客側端末に金額が出て、やめる／確定すると必ず消える。
**同時に会計できるのは 1 件だけ**（配信先 `display/payment/<口>` が 1 本しかないため）。
会計中の注文が別端末で支払い済み・中止になったら、選択も配信も自動で畳む。

支払い済みの控えは下に畳んである。打ち間違いはここから未払いに戻せる。

## 5. 逆向き・例外の遷移（`order.go` の transitions が正）

| from | to | ラベル | 確認ダイアログ |
|---|---|---|---|
| pending | ready | 用意した | なし（トーストで戻せる） |
| pending | cancelled | 中止 | **あり** |
| ready | completed | 渡した | 未払いなら §3 |
| ready | pending | 未処理へ戻す | なし |
| ready | cancelled | 中止 | **あり** |
| completed | ready | 受渡を取消 | なし |
| completed | cancelled | 中止 | **あり** |
| cancelled | pending | 復活 | なし |

作成時に立てられるのは **pending と ready だけ**（`database.rules.json` も同じ）。
completed で作れると、受渡も支払いも通らない注文が入ってしまう。
この一致は `TestRulesCreatableStatuses` が見張っている。

- 中止だけ確認を挟む。他は 1 タップで戻せるため。
- **支払い済みの注文を中止しようとすると、返金額を明示した警告が出る**。
- 中止した注文は売上から外れ、在庫も戻る（`Counts()` が false）。
- `paid` は `true ↔ false` 両方向に打てる。未払いに戻すときは確認ダイアログ。

判定は必ず **サーバー上の最新値** に対して行う（`runTransaction` の中で Go に問う）。
ボタンに焼いた `from` で判定すると、別端末が先に進めていた場合に古い前提で上書きする。

## 6. 画面ごとに何が見えるか

`session`（営業回）で全画面が絞られている。別の回の注文は一切見えない。

| タブ | URL | 表示対象 |
|---|---|---|
| 受付 | （なし） | 商品カード・数え札 |
| 厨房 | `#kitchen` | `status === 'pending'`（先頭を大きく「次に用意する」） |
| 受渡 | `#ready` | `status === 'ready'`（未収は金額を大書き） |
| 支払い口 | `#pay` | 未払い（渡したのに未払いを先頭へ）＋ 支払い済みの控え |
| 金額表示 | `#amount` | `display/payment/<口番号>` の 1 件だけ |
| 記録・売上 | `#records` | 全注文の表・売上・番号札の状況・CSV・営業回の締め |
| 呼び出し表示 | `#call` | `status === 'ready'` かつ **札がある**もの（40秒間強調） |

支払い口と金額表示は `#pay:2` のように口の番号を足せる。

## 7. まとめ

```
                    ┌── 札モード OFF ──→ ready + 未払い ──┐  （厨房を飛ばす）
受付 ── 商品を選ぶ ──┤                                     │
                    └── 札モード ON ───→ pending + 未払い  │
                                              │            │
                                    厨房「用意した」        │
                                    （calledAt 自動）       │
                                              ↓            │
                                            ready ←────────┘
                                              │
                                              ├──→ 呼び出し表示 40秒（札がある注文だけ）
                                              │
                    ┌─────────────────────────┴─────────────────────────┐
                    │ 受渡タブ                                           │ 支払い口タブ
                    ↓                                                   ↓
             支払い済み → [渡した] ──────→ completed        [N円 受け取る]    → paid=true
             未払い    → [N円 受け取って渡した] → paid + completed
                       └ [未払いのまま渡す] → 確認ダイアログ  [受け取って渡した] → paid + completed
                            ├ 受け取って渡す → paid + completed      （ready のときだけ）
                            └ そのまま渡す   → completed / 未払い（取りはぐれ）

    どの状態からでも ──→ cancelled（確認あり・支払い済みなら返金警告）──→ pending（復活）
```
