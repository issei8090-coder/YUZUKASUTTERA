# 注文の一生と、場合分けの一覧

この文書はコードから起こしたもので、推測は含まない。
出典は `internal/order/order.go`（状態遷移の正）と `app.js`（画面の配線）。

---

## 0. なぜ「1本の流れ」に見えないのか

独立した軸が **3本** あり、さらに入口が **2つ** あるため。

| 軸 | 値 | どこで変わるか |
|---|---|---|
| `status` | pending → ready → completed（+ cancelled） | 厨房・受渡・記録表 |
| `paid` | false ↔ true | **受付・支払い口・受渡口のどこからでも** |
| `session` | 営業回（既定 `default`） | 受付の営業回切替 |

`paid` は `status` に混ざっていない（`order.go` の Order 構造体のコメント参照）。
これは意図的で、「渡したのに未払い」＝取りはぐれを集計に出すため。
つまり **status の一本道を追っても支払いは追えない**。これが分かりにくさの中心。

---

## 1. 入口は2つ（`useTags` で割れる）

`useTags` は `config/useTags` に置かれ、**全端末で共有**される（`app.js:859`）。
受付の「番号札を使っています / 使っていません」ボタンで切り替わる。既定は ON。

### 入口A: 番号札モード OFF —— その場渡し

```
受付で商品を選ぶ → 「注文を確定する」
  → placeOrder(immediate=true)
  → BuildOrder: status = completed, paid = true, tag = 0, number = ""
```

- **厨房に出ない。受渡に出ない。支払い口にも出ない**（`paid=true` のため）。
- 記録表と売上には通常の注文とまったく同じに入る。
- 在庫も普通に減る。
- `paid=true` で立てる理由: その場で現金を受け取っているため。未払いで立てると
  支払い口に「渡したのに未払い」が積み上がる（`order.go:840` 付近のコメント）。

**→ この注文はサイクルに乗らない。** 「流れが繋がっていない」と感じる最大の原因。

### 入口B: 番号札モード ON —— 札を渡す

```
受付で商品を選ぶ → 確認 → テンキーで実物の札番号を入力 → 最終確認
  → placeOrder(immediate=false, pickedTag=N)
  → BuildOrder: status = pending, paid = false, tag = N
```

- 札番号は**受付係が実際に取った実物の札**を打つ。山の並び順には依存しない。
- 確定の直前にサーバーの現在値を読み直して、在庫切れ・札の二重使用を弾く
  （`app.js:545` 付近。購読の値は数百ms〜数秒古く、受付2台で事故るため）。
- 札モードONで `immediate=true` が来たら弾く（`app.js:518`）。
  CSS の `display:none` だけで塞いでいると、CSS 1行で事故が戻るため二重に止めている。

## 2. 本流（入口B のあと）

```
[pending]  厨房タブに伝票が並ぶ（受付順・経過3分/6分で色が変わる）
   │
   │  厨房「用意した」
   │    ├ status = ready
   │    └ calledAt = now を同時に書く（呼び出しが自動で始まる）
   ↓
[ready]    受渡タブに出る／呼び出し表示で40秒間強調される
   │
   ├─ 受渡タブ「渡した」  → §3 の分岐へ
   └─ 支払い口タブ        → §4 の分岐へ
   ↓
[completed]
```

「用意した」は確認を挟まない（行列が詰まるため）。代わりにトーストの「戻す」で
7秒間だけ ready→pending に戻せる。

---

## 3. 受渡口で「渡した」を押したときの分岐

`handOver(id)` の中身。

| 条件 | 起きること |
|---|---|
| `paid === true` | そのまま `ready → completed` |
| `paid === false` | **未払い確認ダイアログが開く**（3択） |

未払いダイアログの3択:

| ボタン | 結果 |
|---|---|
| 受け取って渡す | `paid = true` → `completed` |
| そのまま渡す | `completed` のまま **未払い** ＝ 取りはぐれとして集計に残る |
| 戻る | 何もしない |

完全に止めない理由: 現金を受け取ったのに打ち忘れていた場合に行列が止まるため。

---

## 4. 支払い口の分岐

支払い口タブに出るのは `status !== cancelled` の注文のうち:
- **未払い**（`paid=false`）… 上段。`completed` のものを先頭に寄せる（＝取りはぐれ）
- **支払い済み**… 下段。通常は直近20件、番号で絞り込むと全件

会計は **同時に1件だけ**。金額の配信先が `display/payment/<口番号>` の1本しかなく、
2件並行させるとお客様側の画面が入れ替わるため。

| ボタン | 対象 | 結果 |
|---|---|---|
| 受け取る（`pay`） | 全ての未払い | `openCollect(id, false)` → 確定で `paid = true` のみ |
| 受け取って渡した（`paydone`） | **`status === 'ready'` のときだけ出る** | `openCollect(id, true)` → 確定で `paid = true` + `ready → completed` |

会計を開くと客側端末に金額が出て、やめる／確定すると必ず消える。
会計中の注文が別端末で支払い済み・中止になったら、選択も配信も自動で畳む。

## 5. 逆向き・例外の遷移（`order.go` の transitions が正）

| from | to | ラベル | 確認ダイアログ |
|---|---|---|---|
| pending | ready | 用意した | なし（トーストで戻せる） |
| pending | cancelled | 中止 | **あり** |
| ready | completed | 渡した | 未払いなら §3 |
| ready | pending | 未処理へ戻す | なし |
| ready | cancelled | 中止 | **あり** |
| completed | ready | 受渡を取消 | なし |
| completed | cancelled | 中止 | **あり** |
| cancelled | pending | 復活 | なし |

- 中止だけ確認を挟む。他は1タップで戻せるため。
- **支払い済みの注文を中止しようとすると、返金額を明示した警告が出る**
  （受け取った現金が売上のどこにも残らなくなるため）。
- 中止した注文は売上から外れ、在庫も戻る（`Counts()` が false）。
- `paid` は `true ↔ false` 両方向に打てる。打ち消しを認めないとレジの
  打ち間違いが直せず、現金と合わなくなるため。未払いに戻すときは確認ダイアログ。

判定は必ず **サーバー上の最新値** に対して行う（`runTransaction` の中で Go に問う）。
ボタンに焼いた `from` で判定すると、別端末が先に進めていた場合に古い前提で上書きする。
厨房と受渡が同時に触るので実際に起きる。

## 6. 画面ごとに何が見えるか

`session`（営業回）で全画面が絞られている点に注意。別の回の注文は一切見えない。

| タブ | 表示対象 | 並び |
|---|---|---|
| 受付 | 商品カード・数え札（注文一覧は出ない） | — |
| 厨房 | `status === 'pending'` | 受付順。先頭を大きく「次に用意する」 |
| 支払い口 | `status !== 'cancelled'` を未払い／支払い済みに二分 | 未払いは completed を先頭へ |
| 金額表示 | `display/payment/<口番号>` の1件だけ | — |
| 受渡・記録 | 受渡欄は `status === 'ready'`／記録表は全件 | 受付順 |
| 呼び出し表示 | `calledAt` から40秒以内を強調 | — |

## 7. まとめ —— 場合分けの全体像

```
                          ┌── 札モード OFF ──→ completed + paid ──→ 記録だけ（厨房・受渡を通らない）
受付 ── 商品を選ぶ ────────┤
                          └── 札モード ON ───→ pending + 未払い
                                                    │
                                          厨房「用意した」（calledAt 自動）
                                                    ↓
                                                  ready ──→ 呼び出し表示 40秒
                                                    │
                         ┌──────────────────────────┴──────────────────────────┐
                         │ 受渡タブ「渡した」                                    │ 支払い口タブ
                         ↓                                                      ↓
                  paid?  ├ true  → completed                     「受け取る」      → paid=true（status そのまま）
                         └ false → 未払いダイアログ                「受け取って渡した」→ paid=true + completed
                                    ├ 受け取って渡す → paid=true + completed        （ready のときだけ出る）
                                    └ そのまま渡す   → completed / 未払い（取りはぐれ）

    どの状態からでも ──→ cancelled（確認あり・支払い済みなら返金警告）──→ pending（復活）
```
